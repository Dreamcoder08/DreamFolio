## TDD and evidence discipline

- `strict_tdd: true` (`openspec/config.yaml`). Commands per task: `pnpm run test:unit` (`node --test --experimental-strip-types "tests/unit/*.test.ts"`), `pnpm run test:e2e` (`SITE_BASE=/ pnpm run build && playwright test`), outer gate `pnpm run verify`, `pnpm run format:check`.
- RED → GREEN per unit, per design §7.4: unit 1 opens `tests/unit/tokens.test.ts` (A1, A2, A6, A9, A10) RED; unit 2 extends it (A7, A8, A11) and opens `tests/theme-state/theme-state.spec.ts` RED; unit 3 completes both harness file sets; unit 4 writes `tests/unit/transition-contract.test.ts` and **observes it failing against the un-removed universal rule** before making it green in the same unit.
- Honest RED rule: the RED observation is taken against the tree as it stands when the assertion is written. Where an assertion targets a literal an earlier unit already declared, apply **records it as GREEN-by-construction (a regression guard)** and says so in the PR description instead of manufacturing a failing state. Do not delete or weaken an assertion to force a colour change.
- Reconciliation note (design §7.4 assigns "completes" to unit 3): `tests/support/contrast.ts` and `tests/theme-state/theme-state-page.ts` are **opened in unit 2 with the minimum surface its RED reads need**, and **completed in unit 3** (3.1, 3.2). Filenames must not contain `.test.`/`.spec.` so neither runner's glob picks the helper up. No file is created twice and no assertion is deleted.
- Layer rule, per task: `src/styles/portfolio.css` is **entirely unlayered** and beats `src/styles/global.css`'s `@layer base` (unlayered author rules win *before* specificity); unlayered-vs-unlayered and same-layer ties resolve by **source order**. Every task states its file and layer.
- Rollback is per unit, never whole-change (design §8).

## Deviations and non-tasks (apply must not silently add these)

- **`--color-success`, `--color-warning`, `--color-info` are NOT added.** The proposal's unit 1 mentions them; design D7 and §9 override that: they have zero consumers today, three more consumerless keys directly contradict the `design-tokens` delta's "No Consumerless Tokens", and no task or assertion may declare, consume, or exception-list them. `--color-on-surface` is likewise **not added** (`--color-text` already is the on-surface foreground in both modes).
- **`--color-danger` / `--color-on-danger` are kept and exception-listed only** — never wired and never deleted (task 3.5); whether to wire or delete them is a follow-up decision outside this change.
- **No `.tags span` repair exists and none may be added.** `portfolio.css:663-668` (`color: var(--color-text-secondary)`, **no `opacity` in the rule**) reads 9.72:1 dark / 6.28:1 light on `--color-surface-alt` and 10.52:1 dark / 5.60:1 light on `--color-surface`; `portfolio.css:761-765` (`.project-card--civic .tags span { color: currentColor; opacity: 0.62 }`, resolving through `.project-card--civic { color: var(--color-text) }` at `:738-745`) reads 6.73:1 dark / 5.20:1 light (design §9.1). Both pass AA, so neither is repaired. The chip figure that design §9's deviation table withdraws (no selector produces it) **must not reappear** in any task, comment, assertion, or PR description.
- **No luminance-step (ΔL\*) target** is claimed for elevation or for the new state steps. The only step commitments are assertion A8's measured inequalities and A7's floors (design §1.1, §9.1).
- **No conformance language.** Container borders, `--color-border-strong`, `--color-border-hover`, the `opacity` hover pattern and the focus rings are **not** WCAG violations (proposal's framing correction; `design-tokens` "State and Non-Text Contrast Coverage"). `forced-colors` work is **best practice, not a requirement**; WCAG 2.2 §2.4.13 is AAA and out of scope; Apple HIG is not cited.
- **`README.md` is accurate and MUST NOT be rewritten** (Spanish, per repo convention); only `.claude/CLAUDE.md` is corrected (1.10).
- **No screenshot diffing** (`toHaveScreenshot`) may be introduced, **no new dependency** may be added, static output and zero client-side JS are preserved.
- Unchanged by design: `src/components/ui/Navbar.astro`, `src/layouts/BaseLayout.astro`, `public/theme-init.js` (coupling documented only). Light-mode **at-rest** values are frozen; light border ratios, the light `.tag` label (4.81:1) and the light `.btn-primary:hover` label (4.99:1, design §9.1 / proposal "Known Accepted Debt") are recorded as accepted, never repaired.
- Out of this change: wiring vs deleting the danger tokens; making `.site-header`'s glass dark-opaque.
