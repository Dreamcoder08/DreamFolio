# Feature: Verifiable Project Proof

Branch `feat/verifiable-project-proof`. Every featured project shows evidence a visitor can click and check:
repository, demo, CI status, test files and architecture decisions, generated from GitHub with a date, never hand-written.

## Specs

- S1 — User request, verbatim: "Prepara mejor mi portafolio con repositorios, demostraciones, pruebas automatizadas, decisiones arquitectónicas y resultados verificables."
- S2 — Repositories: every featured project links to its public repository (`githubUrl`). Digital Public Peru → `arkelythex/estado`, EdgeTraz Agro → `arkelythex/senzar` (both made public on 2026-11-01 at the user's request: "hacerlos publicos").
- S3 — Demonstrations: a project with a public deployment links to it (`liveUrl`); projects without one show no demo link (never a fake one).
- S4 — Automated tests: show the number of test files found in the repository, linked to the repository, and the latest CI conclusion on the default branch, linked to that run. A failing CI is shown as failing.
- S5 — Architecture decisions: list the ADR files found in the repository (`adr/` or `decisions/` directories), each linked to its file on GitHub.
- S6 — Verifiable results: proof data is generated by `pnpm run sync:proof` from the GitHub API into `src/data/project-proof.json`, stamped with `checkedAt`; a failed sync keeps the committed snapshot and exits 0 (same contract as `sync:repos`). Every proof item has a URL; nothing unlinked is presented as evidence.
- S7 — Regression guard: a unit test fails when a featured project has no `githubUrl` or no proof entry; an e2e test checks the proof section on a project detail page.
- S8 — Docs: README and an architecture note explain the proof model and how to refresh it.
